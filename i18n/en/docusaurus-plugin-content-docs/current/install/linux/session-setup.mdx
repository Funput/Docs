# Advanced Fcitx5 setup on Linux

<div className={styles.guideBody}>

Open the section that matches what you see after installation. If you are still setting up Funput, start with the [Fcitx5 setup steps](./fcitx5.mdx#step-3-wire-session).

## What do you need to check?

<LinuxGuideDisclosure id="where-to-set" label="Settings are missing after signing back in">

**Try restarting the computer once.** The service that reads `environment.d` can stay active after you sign out, so it may not have reloaded the file.

If `fcitx5-diagnose` still reports missing variables, check where your session reads settings.

- **GNOME with GDM or Plasma 5.22 and later.** Use `~/.config/environment.d/fcitx5.conf` when the session reads settings from the systemd user manager.
- **Bash login sessions.** Bash looks for `~/.bash_profile`, then `~/.bash_login`, then `~/.profile`, and reads only the first one that exists. Add the lines with `export` to that file. For example, Fedora and Arch usually ship `~/.bash_profile`, while Ubuntu usually has only `~/.profile`. If none of them exists, create `~/.bash_profile`.
- **Settings for multiple users.** An administrator can use `/etc/profile` on systems that read that file at login.

Set each variable in one place. If you use a different login shell, check which file it reads and follow its syntax. [Fcitx5 documentation on environment variables](https://fcitx-im.org/wiki/Setup_Fcitx_5)

</LinuxGuideDisclosure>

<LinuxGuideDisclosure id="qt-6-8-2" label="Vietnamese typing works except in a Qt app on Wayland">

If Funput works in a text editor but fails in a Qt app, check which desktop you use.

- **KDE Plasma.** [Try an app-specific setting](#undo-im-config-kde) before changing the whole session.
- **GNOME or sway.** For applications using Qt 6.8.2 or later, add this line to `~/.config/environment.d/fcitx5.conf`.

```text
QT_IM_MODULES=wayland;fcitx
```

The new name ends in **S**. If you set it in a Bash file instead of `environment.d`, add quotes, because `;` has its own meaning in Bash: `export QT_IM_MODULES="wayland;fcitx"`. Keep `QT_IM_MODULE=fcitx` if Qt 5 or older Qt 6 applications still need it. Sign out and back in to test. [Fcitx5 documentation for Qt on Wayland](https://fcitx-im.org/wiki/Using_Fcitx_5_on_Wayland)

</LinuxGuideDisclosure>

<LinuxGuideDisclosure id="distro-tools" label="Use your distribution’s setup tool on X11">

If your session check shows `x11`, use the tool for your distribution.

- **Debian, Ubuntu and derivatives.** Run `im-config -n fcitx5`. To make the selection in a window, run `im-config` and choose **fcitx5**.
- **Fedora.** Run `sudo dnf install fcitx5-autostart`.
- **Arch, openSUSE or another distribution.** [Open the X11 setup instructions](./fcitx5.mdx#x11-settings).

Using Wayland? [Choose the setup for your desktop](./fcitx5.mdx#step-3b-env-vars).

</LinuxGuideDisclosure>

<LinuxGuideDisclosure id="undo-im-config-kde" label="The suggestion window flickers on KDE Wayland">

Check whether `GTK_IM_MODULE` or `QT_IM_MODULE` is set for the whole session.

1. If you used `im-config`, open it and choose the desktop default. If you added the variables manually, remove those lines from the file you edited.
2. Apply the [Fcitx5 setup for KDE Wayland](./fcitx5.mdx#wayland-kde-plasma).

If only one XWayland application needs `QT_IM_MODULE`, set it for that application. For example, if the command to open WPS Writer is `wps`:

```bash
env QT_IM_MODULE=fcitx wps
```

</LinuxGuideDisclosure>

<LinuxGuideDisclosure id="kde-no-restart" label="Reload Fcitx5 on KDE Wayland">

If you enabled Fcitx5 in **System Settings → Virtual Keyboard**, **save your work, sign out and sign back in**. KDE connects the input method at login. Running `fcitx5 -r` or choosing **Restart** in the tray can break that connection until the next login.

</LinuxGuideDisclosure>

<LinuxGuideDisclosure id="verify" label="See which settings Fcitx5 loaded">

After signing back in, open Terminal and run:

```bash
fcitx5-diagnose
```

The output shows the variables and input methods Fcitx5 loaded. If Funput is selected but typing still fails, see [Troubleshooting](./troubleshooting.mdx).

</LinuxGuideDisclosure>
