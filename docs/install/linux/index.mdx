# Cài đặt trên Linux

Funput trên Linux là một **engine chạy bên trong Fcitx5** — không phải ứng dụng portable. Trang này là đường cài khuyến nghị: cài từ kho có ký GPG, chạy trên Fcitx5.

Làm đủ 5 bước dưới đây theo thứ tự. Bước hay bị bỏ qua nhất là **bước 3** — và đó cũng là nguyên nhân của gần như mọi trường hợp "cài xong mà không gõ được".

## Bước 1 — Xem bạn đang ở đâu \{#step-1-check-session\}

Funput chạy trong Fcitx5, nên máy cần có Fcitx5. Trước hết ghi lại hai giá trị này, bước 3 sẽ cần:

```bash
echo "$XDG_SESSION_TYPE"     # x11 hoặc wayland
echo "$XDG_CURRENT_DESKTOP"  # GNOME, KDE, sway…
```

:::caution[GNOME và Ubuntu]
Session mặc định ở đây nối vào **IBus**, không phải Fcitx5. Chọn Fcitx5 nghĩa là phải nối lại session (bước 3) rồi **đăng xuất và đăng nhập lại** — cài xong chưa gõ được ngay. Muốn tránh bước đó thì [dùng bản IBus](./ibus.mdx).
:::

## Bước 2 — Thêm kho và cài \{#step-2-add-repo\}

Kho phần mềm Funput (`repo.funput.app`) có ký GPG và tự cập nhật khi có bản phát hành mới. Thêm kho **một lần**, sau đó cài và cập nhật như gói hệ thống bình thường.

<DistroPicker>
<DistroFamily id="debian">

Thêm kho (làm một lần):

```bash
sudo install -d /usr/share/keyrings
curl -fsSL https://repo.funput.app/funput.asc | sudo tee /usr/share/keyrings/funput.asc >/dev/null
sudo tee /etc/apt/sources.list.d/funput.sources >/dev/null <<'REPO'
Types: deb
URIs: https://repo.funput.app/deb
Suites: ./
Signed-By: /usr/share/keyrings/funput.asc
REPO
sudo apt update
```

Cài:

```bash
sudo apt install funput
```

<details>
<summary>Vì sao là <code>.sources</code> chứ không phải <code>.list</code>?</summary>

Đây là định dạng **deb822**. Dạng một dòng `.list` cũ vẫn chạy, nhưng apt 3.0 (Debian 13, Ubuntu 25.04 trở lên) đã báo deprecated trên mỗi lần chạy.

</details>

</DistroFamily>
<DistroFamily id="fedora">

Thêm kho (làm một lần):

```bash
sudo curl -fsSL https://repo.funput.app/funput.repo -o /etc/yum.repos.d/funput.repo
```

Cài:

```bash
sudo dnf install funput
```

<details>
<summary>Vì sao thả thẳng file <code>.repo</code>?</summary>

`dnf config-manager --add-repo <url>` đã bị dnf5 (Fedora 41 trở lên) bỏ. Thả file chạy được trên cả dnf4 lẫn dnf5.

Không cần import khoá GPG bằng tay: `funput.repo` đã khai `gpgkey=`, dnf tự tải khi cài lần đầu.

</details>

</DistroFamily>
<DistroFamily id="suse">

Thêm kho (làm một lần):

```bash
sudo rpm --import https://repo.funput.app/funput.asc
sudo zypper addrepo -gf https://repo.funput.app/rpm/ funput
sudo zypper refresh
```

Cài:

```bash
sudo zypper install funput
```

<details>
<summary>Vì sao phải <code>rpm --import</code> trước?</summary>

Khác dnf, zypper muốn khoá nằm sẵn trong cơ sở dữ liệu rpm trước khi thêm kho.

</details>

</DistroFamily>
<DistroFamily id="arch">

Nhập khoá (làm một lần) — pacman giữ keyring riêng nên phải ký cục bộ thì chữ ký mới được tin:

```bash
curl -fsSL https://repo.funput.app/funput.asc | sudo pacman-key --add -
sudo pacman-key --lsign-key hello@funput.app
```

Thêm kho vào `/etc/pacman.conf`:

```bash
sudo tee -a /etc/pacman.conf <<'REPO'

[funput]
Server = https://repo.funput.app/arch/$arch
REPO
sudo pacman -Sy
```

Cài:

```bash
sudo pacman -S funput
```

<details>
<summary>Giới hạn trên Arch — nên đọc</summary>

**Arch Linux ARM** là một distro riêng, không dùng được kho x86_64 này. Trên máy ARM hãy dùng [đường cài vào `~/.local`](./other-methods.mdx#user-install).

**Đây là gói binary trên một rolling distro.** Gói link vào thư viện Arch tại thời điểm dựng, nên sau một đợt bump soname (fcitx5, ibus, gtk4) nó có thể tạm không nạp được. Kho tự dựng lại **hai tuần một lần** trên Arch mới nhất, nên tình trạng đó được vá trong khoảng hai tuần mà không cần đợi Funput ra bản mới — `pacman -Syu` sẽ nhận bản dựng lại.

</details>

</DistroFamily>
</DistroPicker>

Gói `funput` kéo theo `funput-settings` — ứng dụng Cài đặt — đúng cùng phiên bản. Kho chỉ phục vụ **bản mới nhất**; cần bản cũ thì xem [Cách cài khác](./other-methods.mdx).

## Bước 3 — Nối session vào Fcitx5 \{#step-3-wire-session\}

Funput là engine *bên trong* Fcitx5, nên phải làm hai việc: cho Fcitx5 tự chạy, và trỏ session về nó. Đây là bước hay hỏng nhất — làm đủ cả ba phần dưới đây.

### 3a. Cho Fcitx5 tự khởi động \{#step-3a-autostart\}

**KDE Plasma:** **System Settings → Virtual keyboard → Fcitx 5**. Tài liệu Fcitx5 nói đây là điều kiện để giao thức `text-input` chạy được với ứng dụng Wayland thuần — autostart không thay thế được.

**GNOME và mọi desktop khác:**

```bash
mkdir -p ~/.config/autostart
cp /usr/share/applications/org.fcitx.Fcitx5.desktop ~/.config/autostart/
```

### 3b. Đặt biến môi trường \{#step-3b-env-vars\}

Chọn **đúng một** khối, theo hai giá trị bạn đã in ra ở bước 1.

**`XDG_SESSION_TYPE` là `x11`** — mọi desktop.

Ưu tiên công cụ của distro: nó đặt biến đúng chỗ cho display manager bạn đang dùng, và làm luôn phần 3a.

```bash
# Debian / Ubuntu (và Mint, Pop!_OS…)
im-config -n fcitx5

# Fedora
sudo dnf install fcitx5-autostart
```

Arch, openSUSE và các distro không có công cụ riêng thì đặt tay:

```bash
cat >> ~/.bash_profile <<'CONF'
export XMODIFIERS=@im=fcitx
export GTK_IM_MODULE=fcitx
export QT_IM_MODULE=fcitx
CONF
```

Chọn `~/.bash_profile` vì GDM, SDDM và LightDM đều đọc nó. Dùng shell khác bash, hoặc muốn áp cho mọi người dùng: xem [nơi đặt biến](./session-setup.mdx#where-to-set).

**`XDG_SESSION_TYPE` là `wayland`, `XDG_CURRENT_DESKTOP` là GNOME / sway / compositor wlroots:**

```bash
mkdir -p ~/.config/environment.d
cat > ~/.config/environment.d/fcitx5.conf <<'CONF'
XMODIFIERS=@im=fcitx
QT_IM_MODULE=fcitx
CONF
```

Cố ý **không** có `GTK_IM_MODULE` — GTK 3/4 trên Wayland đã tự nói chuyện với compositor qua `text-input-v3`.

**`XDG_SESSION_TYPE` là `wayland`, `XDG_CURRENT_DESKTOP` là KDE:**

```bash
mkdir -p ~/.config/environment.d
cat > ~/.config/environment.d/fcitx5.conf <<'CONF'
XMODIFIERS=@im=fcitx
CONF
```

Chỉ một dòng. Đặt thêm `GTK_IM_MODULE` hay `QT_IM_MODULE` ở mức global sẽ làm candidate window nhấp nháy trên KWin.

### 3c. Đăng xuất và đăng nhập lại \{#step-3c-relogin\}

:::caution
Biến môi trường chỉ được nạp khi **bắt đầu một session mới**. Mở terminal mới là không đủ, `source` cũng không ăn thua. Đăng xuất/đăng nhập lại — hoặc khởi động lại máy cho chắc.
:::

Ba phần trên phủ hết các trường hợp thường gặp. Nếu bạn dùng Qt 6.8.2 trở lên, dùng display manager không đọc `environment.d`, hoặc đã từng chạy `im-config` và muốn gỡ ra: xem [Session — trường hợp đặc biệt](./session-setup.mdx).

## Bước 4 — Bật Funput \{#step-4-enable\}

1. Mở `fcitx5-configtool`.
2. Bấm **+**, bỏ dấu *Only Show Current Language*, tìm **Funput** (nhóm Vietnamese), thêm vào.
3. Bật/tắt tiếng Việt bằng **`` Ctrl + ` ``** hoặc icon Fcitx5 ở khay hệ thống.

## Bước 5 — Kiểm tra \{#step-5-verify\}

```bash
fcitx5-diagnose
```

Lệnh này soát cả biến môi trường session lẫn addon đã nạp, và chỉ thẳng ra chỗ còn thiếu. Chạy nó **trước khi** đi tìm nguyên nhân ở chỗ khác — nếu có gì sai ở bước 3, nó sẽ nói.

## Sau khi cài \{#after-install\}

- Mở app **Funput** trong menu ứng dụng để chọn **Telex** hoặc **VNI**, smart/eager restore và các tuỳ chọn khác.
- Cài đặt lưu tại `~/.config/Funput/settings.json` — thay đổi có hiệu lực khi focus lại ô nhập liệu.

## Cập nhật \{#update\}

Đã thêm kho ở bước 2 thì cập nhật là **tự động**, đi cùng gói hệ thống:

```bash
sudo apt update && sudo apt upgrade funput   # Debian / Ubuntu
sudo dnf upgrade funput                      # Fedora
sudo zypper update funput                    # openSUSE
sudo pacman -Syu                             # Arch
```

:::tip
Sau khi cập nhật mà bộ gõ không hoạt động bình thường, đăng xuất/đăng nhập lại là cách an toàn cho mọi desktop. (`fcitx5 -r -d` cũng được — **trừ KDE**, xem [cảnh báo](./session-setup.mdx#kde-no-restart).)
:::
